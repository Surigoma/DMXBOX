# Art-Net接続ガイド

[設定・機材](settings.md) | [設定リファレンス](configuration.md)

DMXBOXからArt-Netノードへ照明データを送り、ノードのDMX出力で灯体を動かす手順です。
設定とパケット仕様の詳細は[照明機材・出力仕様](lighting-specifications.md)も参照してください。

## 構成と対応範囲

```text
ブラウザー／HTTP／TCP → DMXBOX → Ethernet → Art-Netノード → DMX灯体
```

DMXBOXは1つの512チャンネルのユニバースを、設定した宛先とPort-Addressへ送信します。
`dmx.groups`を増やしてもユニバース数は増えません。
複数ノードの自動検出・宛先一覧の管理・ユニバースごとの独立パッチは実装していません。
受信したArt-NetデータをDMXBOXの照明制御へ取り込む機能もありません。

## 接続前に用意するもの

- Ethernet接続できるPCとArt-Netノード
- ノードのIPアドレス、サブネットマスク、DMX出力ポートの設定方法
- 灯体のDMX開始アドレスとチャンネルモード
- DMXBOXで一度動作確認したグループ設定

まず受信ノード1台と有線LANで確認すると、宛先と経路の問題を切り分けやすくなります。

## IP設定の例

以下は専用のローカルネットワークを想定した例です。既存環境のアドレスと重複しない値に変更してください。

| 対象 | IPアドレス | サブネットマスク |
| --- | --- | --- |
| PCの有線NIC | `192.168.50.10` | `255.255.255.0` |
| Art-Netノード | `192.168.50.20` | `255.255.255.0` |

1. PCとノードを直接、または同じスイッチへ接続します。
2. PCの有線NICとノードに、上記のような同じサブネットのアドレスを設定します。
3. ノードのDMX出力ポートをArt-Net受信に設定します。
4. DMXBOXの`output.artnet.addr`に、ノードのIPを指定します。

`addr`は受信先です。PC自身のIPではありません。
`192.168.50.20/24`のようなCIDR表記や、`192.168.50.20:6454`のようなポート付き表記は指定しません。
ポートは別の`port`項目で設定します。

## DMXBOXの設定例

次は`output`の値を示す断片です。`input`と`dmx`を含む設定全体は残してください。

```json
{
  "target": ["console", "artnet"],
  "artnet": {
    "addr": "192.168.50.20",
    "port": 6454,
    "net": 0,
    "subuni": 0,
    "universe": 1
  }
}
```

`console`を併用すると物理出力とログを見比べられます。
既存のFTDI・OSC設定を残す場合は、設定全体の必要な項目と`target`の選択も維持します。
`port`を省略すると6454です。現在の実装では、指定ポートを宛先だけでなくPC側のUDP待受にも使用します。
受信ノードに合わせるため、通常は6454のまま使用します。

保存後に再起動の案内があれば再起動します。通常の再読み込みでも出力が作り直されるため、
変更後はノードへの出力をもう一度確認してください。

## Universe番号を合わせる

IPネットワークのサブネットマスクと、Art-NetのSub-Netは別の設定です。
DMXBOXの`subuni`はArt-NetのSub-Net、`universe`はその中の4ビットのUniverseです。

```text
Port-Address = net × 256 + subuni × 16 + universe
```

| net | subuni | universe | パケット上のPort-Address |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 0 |
| 0 | 0 | 1 | 1 |
| 0 | 1 | 0 | 16 |
| 1 | 0 | 0 | 256 |

DMXBOXが受け付ける範囲は`net: 0～127`、`subuni: 0～15`、`universe: 0～15`です。
上の設定例ではPort-Address 1を送信します。0の行は既存設定との対応を確認するための例です。

受信ノードが表示する「Universe 1」が、パケット上の0を指す場合も、1を指す場合もあります。
機器の説明書で0始まり／1始まりを確認し、表示番号だけで判断しないでください。
受信ポートごとにNet／Sub-Net／Universeを設定できる機器では、実際に接続したDMX出力ポートを確認します。

## 複数NIC・VPNの注意

現在の実装は、宛先IPを含むサブネットを持つローカルインターフェースを列挙し、最初に一致したものへバインドします。
NIC名や送信元IPを設定で直接指定する機能はありません。

- 有線LANとWi-Fiを同じサブネットにしないよう、接続構成を確認します。
- VPNや仮想NICに同じ範囲がある場合は、選択が曖昧にならない構成にします。
- OSで疎通できても、宛先を含むローカルサブネットがなければDMXBOXの初期化は失敗します。
- 別サブネットへルーター経由で送る構成は、この送信元選択の制約に注意してください。

## 初回の出力確認

1. ノードの受信Port-AddressをDMXBOXと合わせます。
2. 灯体をノードの該当DMX出力へ接続し、モードと開始チャンネルを合わせます。
3. Browser onlyなどの入力制限を確認してから、ブラウザーでグループを操作します。
4. Fade In／Outで灯体と画面のゲージを見比べます。
5. Cut In／Outを確認し、必要なら外部制御からも同じグループを操作します。

画面のゲージは送信側のソフトウェア状態です。灯体の応答やノードの受信確認ではありません。

## 受信できないときの切り分け

| 確認箇所 | 見る内容 |
| --- | --- |
| DMXBOX | `target`に`artnet`があるか、グループにデバイスがあるか |
| IPとNIC | 宛先がノードのIPか、PC側に一致するサブネットがあるか |
| UDPソケット | 別の照明ソフトが同じローカルIP・UDP 6454を使っていないか |
| ファイアウォール | 使用NICのネットワーク区分とUDP通信の許可 |
| ノード | Art-Net入力、Port-Address、実際のDMX出力ポート |
| 灯体 | チャンネルモード、開始アドレス、DMXケーブル |

ログの`Failed to contain network for interfaces.`は、宛先に一致するローカルサブネットが見つからない場合です。
`Failed to create socket`は、表示された送信元IP・ポートの競合や利用可能性を確認します。
`Drop`は送信時のエラーです。ケーブルやノードの応答を保証するログではありません。

パケットキャプチャを使う場合は`udp.port == 6454`で絞り込み、送信先IP、ArtDMXのPort-Address、
操作したチャンネルの値を順に確認します。独自ポートを使用する場合はフィルターも変更します。
まずPCから送出されているか、次にノードで受信できているか、最後にDMX側を調べます。

## 停止と信号断

終了直前のブラックアウトフレームは明示送信しません。
必要なFade Outを行い、ノードや灯体の信号断時の保持／消灯設定を実機で確認してください。
ネットワーク切断やPC停止を、確実な消灯操作の代わりにしないでください。
