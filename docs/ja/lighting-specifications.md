# DMXBOX照明機材・出力仕様

[English](../en/lighting-specifications.md) | [ドキュメント一覧](README.md) | [設定リファレンス](configuration.md)

## 対象範囲

この文書は、DMXBOXが実装する照明関連の動作、すなわち内部DMXユニバース、対応する論理デバイスモデル、フェード、シリアルDMX出力、Art-Net出力、運用上の制約を説明します。すべてのUSBアダプターや照明機器との互換性を保証するものではありません。本番構成では必ず実機で確認してください。

## DMXユニバース

| 項目 | 値 |
| --- | --- |
| スロット数 | 512 |
| 設定上のスロット番号 | 1～512 |
| 内部値 | 8ビット、0～255 |
| 初期状態 | 全スロット0 |
| 更新レート | `dmx.fps`で設定 |

デバイスの開始チャンネルは1始まりです。デバイスが使うすべてのチャンネルをユニバース内に収める必要があります。現在の実装はデバイス同士のチャンネル重複を拒否しません。意図して十分に検証した場合を除き、重複を避けてください。

## 論理デバイスモデル

### `dimmer`

| 相対スロット | 用途 | Fade Inの目標値 |
| --- | --- | --- |
| 1 | 明るさ | `max[0]` |

1つのDMXスロットを使用します。Fade Outの目標値は0です。

例：

```json
{
    "model": "dimmer",
    "channel": 1,
    "max": [255]
}
```

### `wclight`

| 相対スロット | 用途 | Fade Inの目標値 |
| --- | --- | --- |
| 1 | 寒色 | `max[0]` |
| 2 | 暖色 | `max[1]` |
| 3 | フラッシュ／ストロボ | `max[2]`。通常、フロントエンドは0に保つ |

連続する3スロットを使用するため、開始できる最後のチャンネルは510です。Fade Outでは3スロットすべてを0へ遷移させます。

例：

```json
{
    "model": "wclight",
    "channel": 10,
    "max": [128, 128, 0]
}
```

DMXBOXはRDMを使って物理照明機器のモデルを識別しません。論理モデルと、照明機器側で設定したチャンネルモードを一致させてください。

## グループ

グループには1つ以上の論理デバイスが含まれます。FadeとCutは、グループ内のすべてのデバイスへ適用されます。グループIDはHTTP・TCP APIから使用し、`name`はブラウザ上に表示します。

現在の実装は次を拒否しません。

- ほかのデバイスとチャンネルが重複するデバイス
- 同じチャンネルを複数グループへ登録する構成
- 物理機器側のモードと一致しない設定

設定ファイルをパッチ表として扱い、物理出力を有効にする前に確認してください。

## FadeとCutの動作

操作開始時に、各デバイスは現在のユニバース値を取得します。その値から次の目標へ、各スロットを線形補間します。

- Fade In：設定済みの`max`値
- Fade Out：0

`dmx.fadeInterval`がデフォルトの遷移時間（秒）です。コマンド固有の`duration`が指定された場合は上書きします。`duration:0`は1回の更新で値を切り替えるCutです。0より大きい`interval`は操作開始を遅延します。

同じデバイスで別のFadeを開始すると、その時点の値を始点として、デバイスのタイミングと目標値を置き換えます。

## 出力スケジューリング

DMXループは`dmx.fps`で動作します。デバイス値が変化した場合と、値が変わらない状態でも定期的にレンダラーへ出力します。正の現実的なフレームレートを使用してください。デフォルトは30 FPSです。

## コンソール出力

`console`レンダラーは、物理出力機器を接続しない開発・設定確認向けです。DMXレンダラーの要件を満たし、グループの動作をログから確認できます。

## シリアルDMX（`ftdi`）

現在のシリアルレンダラーは、OSが公開するシリアルポートを使用します。設定名はFTDIですが、実際の互換性は、必要なBreak操作をサポートするポートとしてアダプターとドライバーが認識されるかどうかに依存します。

| シリアル項目 | 値 |
| --- | --- |
| ボーレート | 250000 |
| データビット | 8 |
| パリティ | なし |
| ストップビット | 2 |
| フレーム前のBreak | 1ミリ秒 |
| スタートコード | `0x00` |
| データスロット | 512 |

各出力では、Break、0のスタートコード1バイト、512バイトのユニバース全体を書き込みます。

出力に失敗するとポートを閉じ、後続の出力時に再オープンを試みます。再接続後の復帰は、使用するアダプターで実機確認してください。

ポート名の例：

- Windows：`COM3`
- Linux：`/dev/ttyUSB0`

## Art-Net

DMXBOXはArtDMX UDPパケットを送信します。

| 項目 | 値 |
| --- | --- |
| デフォルトUDPポート | 6454 |
| プロトコルバージョン | 14 |
| ペイロード長 | 512スロット |
| Sequence | 8ビットで加算し、周回後の0を飛ばす |
| Physicalバイト | 0 |
| Port-Address | `net`、`subuni`、`universe`から合成 |

設定した宛先アドレスを含むネットワークを持つローカルインターフェースが送信元として選択されます。そのため、宛先へ到達できるインターフェースがPC上に必要です。

Art-Net入力はDMXBOXの公開機能ではありません。実装は通信と診断ログのためUDPソケットで受信しますが、受信したArt-NetデータはDMXユニバースへ反映しません。

### 受信タイムアウト

受信ループは停止要求を確認するため、500ミリ秒の読み取り期限を設定します。期限までにパケットを受信しなくても待受と送信を継続します。タイムアウト以外のソケット読み取りエラーが発生した場合は、Art-Netを停止してエラーを記録します。

## OSC出力

OSCはDMX照明データではなく、ミキサーのMute/Unmute制御に使用します。設定した各チャンネルについて、OSCアドレステンプレート内の`{}`を置換し、`int32`または`float32`の値を送信します。`inverse`はMuteとUnmuteの値を反転します。

## 起動・再読み込み・終了

- 内部DMXユニバースは0から開始します。
- 論理デバイスの初期化時は、通常レンダリングを始める前にユニバースをクリアします。
- 設定を保存するとモジュールが再読み込みされ、設定済みの出力が作り直されます。
- 正常終了時はシリアルDMXとArt-Netの通信を閉じます。
- 現在、出力を閉じる直前に全スロット0のブラックアウトフレームを明示送信しません。

終了後の物理的な状態は、受信機器や照明機器の信号断時動作に依存します。システム全体として必要な動作を定義・検証し、プロセス終了だけでブラックアウトが保証されるとは考えないでください。

## 本番前の実機確認

- 物理照明機器のモードと各論理デバイスモデルが一致することを確認します。
- すべてのデバイスが1～512に収まり、意図せず重複していないことを確認します。
- 1、255/256、末尾付近のチャンネル境界を確認します。
- Fade In、Fade Out、Cut In、Cut Outを実機で確認します。
- シリアルDMXではUSB切断・再接続を確認します。
- Art-Netではネットワークインターフェース選択と受信機断を確認します。
- 設定再読み込み中とプロセス終了時の状態を確認します。
- 非常時に操作できるハードウェア側のブラックアウトまたは電源制御手段を用意します。
