# DMXBOX利用者ガイド

[English](../en/user-guide.md) | [ドキュメント一覧](README.md)

## 想定する利用環境

DMXBOXは、バックエンドとブラウザ画面を同じPC上で動かす構成を主な利用形態としています。デフォルトのHTTP待受は`127.0.0.1:8080`であり、設定を変更しない限り、ほかのPCには公開されません。

リリースビルドはWindows x86-64、Linux x86-64、Linux ARM64向けです。

## リリース内容

次の項目を同じディレクトリに配置します。

```text
dmxbox_<platform>_<version>[.exe]
static/
[config.json]
```

DMXBOXはカレントディレクトリを基準に`config.json`と`static/`を探します。初回起動時の`config.json`は任意で、存在しなければ生成されます。実行ファイルと`static/`があるディレクトリから起動してください。

## 初回起動

1. リリースZIPを展開します。
2. ZIPに`config.json`が含まれる場合は、HTTP待受と出力先を確認します。
3. 実行ファイルを起動します。
4. `http://localhost:8080/gui/`を開きます。
5. 本番の照明機器を接続・有効化する前に設定内容を確認します。

`config.json`がない場合は、カレントディレクトリにデフォルト設定が生成されます。デフォルトの出力先は`console`で、DMXハードウェアを接続せずに動作確認できます。

## 画面

### コントロール画面

設定済みのDMXグループを表示します。各グループからFade InとFade Outを実行できます。Cut操作は即時に値を切り替えます。OSC出力が有効な場合はMuteとUnmuteも表示されます。

2つのFadeボタンにまたがる1本の背景ゲージで、グループの設定済み最大値に対する現在のDMX出力レベルを表します。Fade Inで増え、Fade Outで減ります。ボタンの上にグループ名、待機中・フェード中・停止中の状態、出力の割合を表示し、TCPや別のブラウザからの操作にも追従します。割合はフェードの完了率ではなく出力レベルです。FadeとMuteの状態は1本のHTTPストリームで受信し、バックエンドは250ミリ秒ごとに確認して変更時だけ配信します。値は機器からの実測値ではなく、バックエンドが出力しているDMX値に基づきます。接続が切れた場合は`State unavailable`と表示しますが、操作ボタンは使用でき、3秒後に自動再接続します。

Mute／Unmuteの上には、最後にOSC送信した状態を`Muted`／`Unmuted`と表示し、対応するボタンを強調します。TCPや別のブラウザからの操作にも追従します。これは送信先機器の実測状態ではありません。起動直後、送信途中、送信エラー、状態の取得失敗時は`State unavailable`と表示します。状態が不明でも操作できます。

### 設定画面

次の項目を編集できます。

- HTTP・TCP入力
- FTDI・Art-Net・OSC出力
- DMXフレームレートとフェード時間
- DMXグループ、デバイスモデル、チャンネル、最大値

編集後は未保存の表示が出ます。**Update**を押すと設定全体を保存し、成功後に未保存の表示を解除します。保存に失敗した場合は編集内容を保持します。未保存のまま別画面へ移る際には、編集を続けるか破棄して移るかを確認します。保存後はバックエンドモジュールが再読み込みされるため、使用中の接続が作り直される場合があります。

設定画面下部の**Control mode**欄を開くと、**Browser only**を切り替えられます。制御側で問題が起きた際に、TCPなどからの制御を止めてブラウザから手動操作するためのモードです。切り替えは**Update**を押さずに即時反映され、バックエンドの再起動で解除されます。現在のON／OFFは折りたたみ見出しと操作画面にも表示され、状態が取得できない場合は`Unavailable`と表示します。

## 終了

ターミナルでCtrl+Cを押します。終了ログを確認してから、ターミナルを閉じたり接続機器を取り外したりしてください。

## 更新

1. 現在のプロセスを終了します。
2. `config.json`をバックアップします。
3. 新しいリリースを別ディレクトリへ展開します。
4. リリースノートに設定変更がないか確認してから、既存設定をコピーします。
5. 新しい実行ファイルを起動し、`/api/v1/health`とコントロール画面を確認します。
6. 実機確認が終わるまで以前のリリースを残します。

## トラブルシューティング

### ブラウザ画面が開かない

- プロセスが終了していないか確認します。
- 開発用URLではなく`http://localhost:8080/gui/`を開きます。
- 8080番ポートをほかのアプリが使用していないか確認します。
- `config.json`の`input.http.ip`と`input.http.port`を確認します。

### 設定を読み込めない

- JSONの構文を確認します。
- `config.json`があるディレクトリからDMXBOXを起動します。
- 正常だった設定へ戻すか、不正なファイルを一時的に移動してデフォルト設定を生成します。

### シリアルDMXを開けない

- `COM3`や`/dev/ttyUSB0`など、設定したポートを確認します。
- 同じデバイスを使用しているほかのアプリを終了します。
- Linuxでは、実行ユーザーにシリアルデバイスへのアクセス権があるか確認します。
- USB機器を再接続し、デバイス名が変わっていないか確認します。

### Art-Netを受信側で確認できない

- 宛先アドレスと使用するネットワークインターフェースを確認します。
- Net、Sub-Universe、Universeを確認します。
- OSのファイアウォールと受信機器の設定を確認します。

### OSCのMuteが動作しない

- `output.target`に`osc`が含まれているか確認します。
- 宛先IP、ポート、アドレス形式、データ型、チャンネル一覧を確認します。
- 受信するミキサーが通常値と反転値のどちらを要求するか確認します。

実行時の診断情報は標準出力へ記録されます。不具合を報告する際は、関連するログ、OS、リリースバージョン、機密情報を除いた設定を添えてください。
